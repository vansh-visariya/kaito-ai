Hybrid retrieval vs. HyDE — when each breaks down
RAG
Docs filed
Compare three approaches to retrieval-augmented generation — naive top-k, hybrid BM25 + vector, and HyDE — and tell me when each one breaks down.
K

Each of the three approaches fails for a different reason, and the failure modes are not interchangeable.

Naive top-k is the brittle baseline. It assumes the query's literal terms appear in the passage that answers it — which is fine when the user knows the document's vocabulary, and catastrophic when they don't. Paraphrased questions, technical jargon mismatches, and cross-lingual retrieval all expose it.1

Hybrid BM25 + vector recovers some of that by fusing lexical and semantic signals, usually through reciprocal-rank fusion.2 It is the strongest default for enterprise corpora, but the two retrievers can quietly reinforce each other's blind spots when both miss the same region of the embedding space.

HyDE (Hypothetical Document Embeddings) sidesteps the vocabulary mismatch by generating a fake answer and searching with that. The known failure mode is hallucination leakage: the retriever finds passages that look like the hypothetical answer, which may have nothing to do with the real evidence.3 Use it on thin queries, never on factual ones where provenance matters.

A practical ordering: start with hybrid, fall back to HyDE only when queries are short and open-ended, and treat naive top-k as the floor you measure against.
